# Ceba: Multilingual Banking Support Chatbot

> **Unofficial demo / portfolio project.** Not affiliated with, endorsed by, or connected to the Commonwealth Bank of Australia. Answers are generated by an AI model from publicly available support pages, may be inaccurate, and are not financial advice.

Ceba is a customer-support chatbot that answers banking questions in the customer's own language. It detects the language of each message, finds the most relevant support pages in a search index, asks an Azure OpenAI model to write a short answer from those pages only, and replies in the original language with links to its sources.

## Features

- **Multilingual:** detects the language of each question and translates in both directions.
- **Grounded answers:** retrieval-augmented generation over 21 indexed CommBank support pages, so replies come from real documents rather than the model's memory.
- **Cited sources:** every answer links to the pages it used.
- **Secure by design:** secrets live in Azure Key Vault and are read through a managed identity, with no keys in the code.

## How it works

1. The React client posts the question to an Azure Function (`/api/chatbot_function`).
2. Azure Translator detects the language, and non-English questions are translated to English.
3. Azure OpenAI rewrites the question as a search query, and Azure AI Search (indexed from Cosmos DB) returns the top 3 support pages.
4. Azure OpenAI answers using those pages.
5. The answer is translated back into the user's language and returned with its source links.

## Tech stack

| Layer | Technology |
|---|---|

## Configuration

### Function App settings
Set these in `local.settings.json` (copy `local.settings.example.json`) for local runs, and as application settings on the Function App in Azure.

| Setting | Purpose |
|---|---|
| `KEY_VAULT_NAME` | Name of the Key Vault holding the secrets below |
| `AZURE_TRANSLATE_ENDPOINT` | `https://api.cognitive.microsofttranslator.com` (**no trailing slash**) |
| `AZURE_TRANSLATE_REGION` | *Optional.* Region of the Translator resource (default `australiaeast`) |
| `SERVICE_NAME` | Azure AI Search service name (the part before `.search.windows.net`) |
| `INDEX_NAME` | Search index name |
| `AZURE_OPENAI_ENDPOINT` | e.g. `https://<resource>.openai.azure.com/` |
| `AZURE_OPENAI_DEPLOYMENT` | Name of the chat model **deployment** |
| `AZURE_OPENAI_QUERY_DEPLOYMENT` | *Optional.* Cheaper deployment for the query-rewrite step |
| `AZURE_OPENAI_API_VERSION` | *Optional.* Default `2024-06-01` |
| `USE_ENTRA_AUTH` | *Optional.* `true` = keyless OpenAI via managed identity |

### Key Vault secrets

| Secret name | Contains |
|---|---|
| `detect-language` | Azure Translator key |
| `admin-key` | Azure AI Search admin key |
| `azure-openai-api-key` | Azure OpenAI key (not needed when `USE_ENTRA_AUTH=true`) |

The Function App's managed identity needs the **Key Vault Secrets User** role on the vault. For local runs, sign in with `az login` and give your own account the same role.

> **Model note:** the code sends `max_tokens` and `temperature`, which GPT-5-family and o-series reasoning models reject. Deploy a non-reasoning chat model (a GPT-4o / GPT-4.1-class model, or `gpt-5-chat`).

## Run locally

```bash
# Backend
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
az login
cp local.settings.example.json local.settings.json    # then fill in your values
func start                                            # http://localhost:7071/api/chatbot_function

# Frontend (second terminal)
cd chatbot-client
cp .env.example .env
npm install
npm start                                             # http://localhost:3000
```

## Build the knowledge base (run once)

Copy `.env.example` to `.env` in the repo root and fill it in, then:

```bash
pip install -r RAG_prep/requirements.txt
python RAG_prep/run_all.py            # needs Microsoft Edge installed
```

`run_all.py` runs, in order: `scrape_data.py` (to `RAG_prep/all_documents.json`), `upload_docs.py` (Cosmos DB), `create_datasource.py` (an AI Search data source named `cba-support-docs`) and `setup_search.py` (index and indexer), then waits for the indexer to finish.

## Deploy

1. **Backend:** create a Function App (Flex Consumption, Python 3.11) and add the settings above. Turn on its system-assigned managed identity and grant it *Key Vault Secrets User* on the vault. Then publish from the repo root with `func azure functionapp publish <function-app-name> --python`, and add the frontend's URL under the Function App's **CORS** settings.
2. **Frontend:** create an Azure Static Web App (deployment source *Other*). In GitHub add the repository secret `AZURE_STATIC_WEB_APPS_API_TOKEN` (the app's deployment token) and the repository **variable** `REACT_APP_FUNCTION_URL` (`https://<function-app-hostname>/api/chatbot_function`). Pushes to `main` that touch `chatbot-client/` deploy automatically via `.github/workflows/deploy_frontend.yaml`.
